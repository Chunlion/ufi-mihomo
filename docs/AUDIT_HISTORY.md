## audit.5：2026-10-11，`93ecfcb`

问题与修复：

| 问题 | 修复 | 为什么这样设计 |
| --- | --- | --- |
| 原生 boot PATH 没有 curl | 复用绝对路径发现，普通可执行文件并实际 `--version` 探测；独立 Service curl 迁移 | 页面环境可运行不代表开机环境可运行；旧 preservation 标记不能跳过新补丁 |
| 核心已起但重载失败被误读为成功 | 分开核心/API/面板重载/body 收尾，传播 `service_finalize_failed` | 保留可用核心及准确失败原因，不能用 PID 代替最终结果 |
| 停止进度先于租约释放结束 | 最终成功由完整操作收尾决定 | 租约/回执失败仍需阻止后续写入 |
| 页面仍活跃但没有瞬时 Shell 任务 | frontend 期限和续期；恢复锁内再次核对 | 无 Shell 进程不等于页面已放弃操作 |
| 普通停止未取得租约却进入恢复清理 | 拒绝无租约停止，后端复核 resume owner | 防止清理另一页面的网络 |
| 任务登记前目录被另一请求移除 | 登记与目录清理共用 recovery lock | 保证任务回执不会因调度窗口丢失 |

原始 DIFF-REPORT 明确：固定 secret、六种 profile、端口、Controller HTTP 补丁、Provider、安装/配置/订阅事务和网络清理逻辑不是该轮重新设计的内容。竞态故障有隔离对照，不宣称曾在 F50 上自然发生。

2026-10-11 19:52:17 的真实原生开机复验观察到核心/API/重载/body 标记成功、无 curl_127、无残留锁/租约，API/面板 200、HTTP/SOCKS HTTPS 204。原生启动器未保存最终 Shell 退出码，不能补写 boot exit 0；该次未重测所有 TUN/竞态/长稳项目。
