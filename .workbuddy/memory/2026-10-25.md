## 「代理不通」二次排查（10:55）：废弃 fake IP 撞上 private_ip 规则

现象：用户报设备无法正常代理，但内核正常。

设备侧全部正常：

- `Clash.Core` PID 5945 在跑；`mangle KANO_F50_PRE` 里 TPROXY 规则命中 **4352 个 TCP 包**；策略路由 `ip rule 1777: fwmark 0x10000000 → table 17666`，表内 `local default dev lo` 存在。

日志暴露真因：

```
[TCP] dial DIRECT (match RuleSet/private_ip) 192.168.0.248:50209 --> 198.18.0.91:443
  error: dial tcp 198.18.0.91:443: i/o timeout
```

- `198.18.0.0/15` 属保留网段，被 `private_ip` 规则集匹配 → DIRECT → 直接拨 fake IP → 超时（每次 5 秒）。
- 最近 40 条超时**全部来自 `192.168.0.248`**（用户 PC 的 SNAT 路径），其他客户端无影响；累计 1362 条。
- 本机实测：`github.com → 198.18.0.83`、`www.google.com → 198.18.0.32`（上一代 fake IP），而 `yt3.ggpht.com → 104.244.42.197`（真实）、`baidu.com` 200。即**按域名分别缓存**，只有早期解析过的名字还钉着 fake IP。

修复：本机 `ipconfig /flushdns` **无效** —— 缓存活在 ICS(`SharedAccess`, svchost) 进程内存里，必须管理员 `Restart-Service SharedAccess -Force` 或重启本机。无管理员权限做不了。

结论：fake-ip → redir-host 切换后，唯一残留风险就是客户端旧缓存；没有 fake-ip 池之后不会再产生。
