## P0：三个死参数

### P0-1 `managedDashboard` 参数名错误

**问题**：`normalizeManagedTemplateObject` 调 `applyRequiredF50Fields(config, { managedDashboard: generated })`，但函数签名只有 `{ preservedSecret, preserveConfig }`。`generated` 从未传入，`preserveConfig` 恒为 `false`，导致模板模式下 `unified-delay` 永远被强制写 `true`、`external-ui-name` 永远被删——即使 `generated=false`（用户已有模板）。

**方案**：改为 `applyRequiredF50Fields(config, { preserveConfig: !generated })`。生成的新模板仍统一补默认值；用户已有模板尊重其 `unified-delay` 设置。

**收益**：修掉一个静默失效的参数，`generated` 语义第一次真正生效。

**位置**：`猫猫TProxy.js:6014`（原 :5952）

### P0-2 `tproxyPort` 死参数

**问题**：两处 `normalizeManagedTemplateObject(..., { tproxyPort })` 传入的参数，函数签名里根本没有，纯噪音；同时每次都执行一次无意义的 `detectF50TproxyPort()`。

**方案**：删除变量与传参（两处）。`detectF50TproxyPort` 定义替换为注释，说明端口属于受控集合。

**收益**：消除误导性代码，减少两条无效调用链。

**位置**：`:5300`、`:5335`、`:6563`、`:6570`、`:5748`

### P0-3 端口常量与提示文案不一致

**问题**：`sanitizeConfigForTProxy` 用 `getPositivePort(runtimeOptions.tproxy_port, ...)` 取端口，但实际写入配置的是 `F50_PORTS.tproxy`（常量）。用户在 options 里写 9999，提示说「端口 9999」，配置里却是 7895。

**方案**：提示文案直接用 `F50_PORTS.tproxy`；`getPositivePort` 已无调用者，一并删除。

**收益**：提示与实际配置一致，不再给出错误信息。

**位置**：`:8401`、`:8455`、`:5513`

## P1：改写覆写基线

**问题**：非 `subscription_original` 模式下，`out = clone(profile)`，用户配置只被搬走 9 个顶层键，其余全部丢弃。`sniffer`、`dns`、`tun.mtu`、`log-level`、`profile.*` 等一律回到固定值。

**方案**：`out` 仍以 profile 打底（保证缺失字段有默认值、行为不变），然后遍历用户配置，把**非受控键**覆盖上去：

```js
const CONTROLLED_TOP_KEYS = ['mode','bind-address','ipv6','external-controller','external-ui','external-ui-url','tproxy-port','allow-lan'];
const CONTROLLED_DNS_KEYS = ['enable','listen','ipv6'];
const CONTROLLED_TUN_KEYS = ['enable','device','auto-route','auto-redirect','strict-route','dns-hijack'];
```

受控键继续由 profile 强制，其余透传。

**收益**：用户配置的 `log-level`、`find-process-mode`、`tcp-concurrent`、`keep-alive-interval`、`geodata-*`、`unified-delay`、`port`/`socks-port`/`mixed-port`、`hosts`、`sub-rules` 及任何未列出的标准字段都保留。缺失字段仍自动补齐，默认行为不变。

**位置**：`猫猫TProxy.js:2876-2910`（`createPrivateRouteLogic.runtime`）

## P2：子键级合并

### dns / tun / sniffer / profile

**问题**：整组替换。用户写 `dns.nameserver` 或 `tun.mtu` 会被整段覆盖。

**方案**：

- `dns`：`mergePlain(profile.dns, user.dns)` 后把 `enable/listen/ipv6` 三个受控子键还原为 profile 值；
- `tun`：同样合并，受控子键（`enable/device/auto-route/auto-redirect/strict-route/dns-hijack`）还原为 profile 值，profile 没有的受控键则删除；`mtu` 必须为 1280~65535 的整数，否则报错；
- `sniffer`、`profile`：一层合并，用户值优先。

新增 `checkLocalPorts`：`port`/`socks-port`/`mixed-port` 不能重复，也不能占用受管端口（`tproxy-port`、`dns.listen`、`external-controller`）。

**收益**：用户可自定义 DNS 上游、fake-ip 过滤、hosts、TUN MTU、嗅探规则，而接管端口、设备名、路由开关仍被锁死。

**位置**：`猫猫TProxy.js:2832-2874`（受控集合与 `mergeDnsValue`/`mergeTunValue`/`checkLocalPorts`）与 `:2880-2891`（runtime 合并分支）

### `nameserver-policy` 不再覆盖用户策略

**问题**：`rule-providers` 里有 `cn_domain`/`private_domain`/`add_direct_domain` 时，无条件写入 `rule-set:<name>` 策略，覆盖用户同名项。

**方案**：只在用户没有该键时补充。

**收益**：用户可以把国内域名指到自己的 DNS，不影响其它策略。

**位置**：`:2925-2933`

## P3：可见性

**方案**：整形结束时比较 source 与 out 的受控键，把被纠正的键写入 `x-f50-overridden`（Mihomo 忽略 `x-` 前缀）。没有覆盖时删除该键，避免污染。

**收益**：用户保存后发现配置「被改了」时，能在 config.yaml 里直接看到是哪几项、哪一层（`dns.listen`、`tun.enable`）。

**位置**：`:2935-2947`

## 未实施的项与理由

| 点位 | 决定 | 理由 |
|---|---|---|
| 11/12 节点 `interface-name`/`routing-mark` | 保持删除 | Android 上 Mihomo 大概率不接受这两个字段，保留会导致核心启动失败。静默删除改为由 `x-f50-overridden` 之外的方式提示（后续做） |
| 13 `rule-providers.*.proxy` → `DIRECT` | 保持强制 | 规则集走代理下载在设备上易失败，`DIRECT` 是稳定默认。要放行需要先在实机验证代理下载 |
| 18 `proxy-groups[].use` 全量替换 | 保持 | `use` 必须与当前 provider 集合一致，否则引用悬空会让核心报错。用户表达子集可以用 `filter`/`exclude-filter` |
| 19 `rules` 在 `generated` 时重建 | 保持 | 这是「生成新模板」的定义行为，非 generated 时不触发 |
| 20 分类 GEOIP 规则删除 | 保持 | 新内核已移除这些分类，保留会导致 `Core -t` 失败。改为写入后按报错回删需要额外一轮 Core 调用，收益不抵成本 |
| `tproxy-port` 可配置 | 不放行 | iptables、DNS nat、启动校验三处硬编码，改动面覆盖组件包，属于独立议题 |
