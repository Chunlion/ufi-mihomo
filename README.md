# 猫猫 TProxy（ufi-mihomo）

中兴 F50 等 UFI-TOOLS 随身 Wi-Fi 的 mihomo（Clash.Meta）透明代理插件。装好插件，设备自己跑代理、订阅、规则和面板，不需要电脑常开。

## 猫猫 TProxy

`猫猫TProxy.js` 是主插件：组件安装、配置生成、网络接管、订阅更新、面板、诊断和卸载，全部在插件页里完成。

**接管**

- TProxy（透明代理）、TUN、关闭接管三种流量模式；切换时补齐 IPv4/IPv6 与 DNS 字段，并重新应用、校验接管路由。
- IPv6 双栈；TUN 协议栈自动选择，优先 mips，旧内核 IPv4 回退 mixed，双栈回退 gVisor。
- 直连设备与私网定向代理：按 MAC / IP 记备注并排除接管，维护直连域名与 IP 清单。

**订阅**

- 公网 HTTP / HTTPS 订阅，可多条并存、单条禁用；禁用后保留链接，不参与生成和更新。
- 节点处理两种：Mihomo HTTP Provider（由核心按间隔刷新），或设备本地转换（支持分享链接，数据不经第三方转换站）。
- 自动更新：可选每 1、6、12、24 小时。核心停止时暂停，核心启动或设备重启后自动恢复。
- 备用节点：直连拉不到订阅时改用备用节点下载，成功会提示本次由备用节点完成；失败不会覆盖原有节点缓存。
- 订阅请求头可自定义 User-Agent。

**配置与规则**

- 统一使用本地模板，规则和策略组由模板提供；订阅更新不会冲掉手改内容。
- 三种改法：YAML 覆写、JS 覆写、图形规则。保存后点“应用模板”生效。
- 节点 DNS 策略：按节点域名指定多条 DNS，支持复制粘贴 YAML。
- 上传或编辑 `config.yaml` 后，保存订阅默认不替换自定义配置；需要替换时手动勾选。

**Gist 同步**

- 配置加密后存进自己的 Gist，用 age 私钥解密，多台设备共用一份配置；同步间隔 1、6、12 或 24 小时。
- 私钥只在本机解密使用，不随请求明文传输。

**面板与诊断**

- 内置 Zashboard 面板，可在插件页内嵌打开，也可另开窗口。
- “状态与日志”一次汇总核心进程、控制 API、接管规则、订阅来源和面板连通性。
- 配置、安装、订阅更新或端口检查失败时，保留或恢复原有可用数据，不留半套状态。

**维护**

- 导出配置包，备份模板、覆写、订阅源和设备备注。
- 清理缓存、重启/停止核心、开机自启开关。
- 完整卸载：清理组件、自启和接管规则。

## 另外两个插件

可选，和猫猫互不依赖，各自在自己的面板里装卸。

| 文件 | 作用 |
|---|---|
| `开机自启修复.js` | 增强所有插件的开机启动：修复启动脚本被拆散、重复或为空的问题，补上重试与故障恢复。装好后点“安装 / 修复”。 |
| `USB网络模式切换插件.js` | 切换 USB 网卡模式（CDC-NCM / CDC-ECM / RNDIS），管理自动修复和有线 ADB。切换会短暂断开有线连接。 |

## 安装

设备 `/data` 需要至少 50 MB 可用空间。

1. 打开 UFI-TOOLS 管理页（通常为 `http://192.168.0.1:2333/`），进入“插件功能”。
2. 上传并提交 `猫猫TProxy.js`。
3. 刷新页面，展开“猫猫”，点击“安装 / 启动”。首次安装请用“导入组件包”装入随附的 `tproxy-yq.zip`，再启动。
4. 需要开机修复或 USB 模式切换时，再上传对应插件。

切换 USB 模式前请确认能用 F50 的 Wi-Fi 进入管理页，否则有线断开后可能无法操作。

### 默认端口

| 用途 | 端口 |
|---|---:|
| HTTP 代理 | `7890` |
| SOCKS 代理 | `7891` |
| Mixed 代理 | `7892` |
| TProxy 接管 | `7895` |
| Mihomo DNS | `1053` |
| 控制 API 与 Zashboard | `7788` |

## 配置约定

- 订阅只接受不含用户名或密码的公网 HTTP、HTTPS 地址；内网、回环和保留地址会被拒绝。
- 旧“订阅原配置”不会自动覆盖。在订阅设置中启用链接，点“保存并更新”并确认迁移；旧配置及来源文件保留在界面显示的备份目录。
- 切换 TProxy、TUN 或关闭接管时，插件会调整必要的网络字段，YAML 注释和排版不会保留。
- 内核缺少 IPv6 NAT 时，保留 IPv4 DNS 劫持和 IPv6 接管；IPv6 DNS 无法通过 NAT 重定向。
- mips 协议栈需要 [Mihomo v1.19.31](https://github.com/MetaCubeX/mihomo/releases/tag/v1.19.31) 或以上，保存和启动前检查版本；版本读取失败时停止操作。手动选择保留。

## 状态与排错

| 状态 | 含义 |
|---|---|
| `not_installed` | 未安装 |
| `damaged` | 组件、架构、权限或配置预检未通过 |
| `installed_stopped` | 安装完整，核心未运行 |
| `running_api_unavailable` | 核心已运行，控制 API 不可用 |
| `healthy` | 核心和控制 API 均正常 |

具体原因以面板诊断结果为准。

## 更新与卸载

主插件发布版本为 `9.0.0`；`F50_COMPAT_VERSION`、控制器版本文件和 Service 标记仍使用协议版本 `8.0.0-compat.2.3`，无需随发布版本修改。配置迁移按配置来源和已保存订阅判断。

完整组件包 `tproxy-yq.zip` 已包含 GistSync、age 及同步脚本，导入一次即可，Gist 页面无需另装组件。更新保留已有链接、私钥和同步间隔。

当前 GistSync RC4 完整包尚未在线发布，“在线安装 / 更新”会提示导入随附组件包，不会下载缺少 GistSync 的旧包。“安装 / 启动”检测到已安装的兼容组件时只启动核心。

GistSync 的构建、复测、安全边界和实机待验证项目见 [维护说明](docs/gist-sync.md)。

原 `_Go` 版用户先停用旧插件，再上传 `猫猫TProxy.js`。完整卸载用猫猫面板中的“卸载插件”；开机修复插件需要在自己的面板中单独卸载。

## 源码

辅助程序 Go 源码在 `binary-helper/`，构建脚本为 `scripts/build_helper.py`，默认同时构建 GistSync 并刷新完整组件 ZIP。`clashctl` 的完整原始 Go 源码尚未取得；ARM64 HTTP 兼容修复的生成代码保存在 `scripts/patch_controller_http.js`，可从仓库组件包重建修复后的控制器：

```sh
node scripts/patch_controller_http.js tproxy-yq.zip clashctl_arm64.http
```

输出文件必须不存在。设备端修复和写入校验代码在 `猫猫TProxy.js` 中。
