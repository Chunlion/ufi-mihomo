日期：2026-10-14。源码对比基线：`b21155e`。插件保持 v9.0.0，Controller 兼容版本保持 `8.0.0-compat.2.3`。

## 一、审计

### 结构与体积

体积减少 **114 字节，约 0.0193%**。模板字符串源码的减少未改变生成 Shell 的大小或内容。

修改前按连续源码区域划分：

| 区域 | 字节 | 占比 |
|---|---:|---:|
| F50 基础、兼容及安装 helpers | 137,606 | 23.4% |
| 私网路由、网络状态及卸载入口 | 42,283 | 7.2% |
| 主体 UI、订阅、模板和配置事务 | 409,305 | 69.5% |

最大的区域是主体 UI/订阅/模板事务。最大的具名函数是 `showPolicyToolsDialog`（23,145 字节），其次为 `buildF50InstallScript`（18,656）、`restoreConfigPackageFromFile`（15,819）、`createPrivateRouteLogic`（14,324）和 `buildF50OriginalServicePatchScript`（9,823）。这些函数大小按 AST 范围统计。

重复统计采用原始整行完全一致、非注释、去除首尾空白后长度至少 40 字符的口径。首次出现后的重复为 **135 行，占总行数 1.16%**，共 8,598 字节。这是文本重复指标，包含不同安全边界中的必要校验，不能直接作为可删除量。

### 重复逻辑

本次未确认必须修复的 P0 问题。

| 项目 | 发现与处理 | 优先级 | 修改风险 |
|---|---|---|---|
| symlink 检查 | 必须区分允许不存在、普通文件和安全目录；保留调用点校验 | P2 | 高，不实施统一运行时 helper |
| lock 检查 | lease、frontend、恢复锁与安装锁的等待、归属、回收规则不同 | P2 | 高，保持原样 |
| 文件安全检查 | `-e`、`-f`、`-s`、`-L` 组合不能互换 | P2 | 高，保持原样 |
| hash 校验 | Controller 白名单、区间、备份、提交后和回执校验用途不同；仅集中固定 hash | P1 | 低，生成检查保持原样 |
| 临时目录 | 安装可能保留 journal/backup；恢复检查清理结果；Service patch 有独立 trap | P2 | 高，保持生命周期 |
| 原子替换 | 配置使用 600；Service 使用 755 或原权限；仅复用完全相同的文本 | P1 | 低，逐字节比较后实施 |

`set -e`、subshell、trap、提交标记、失败退出码和提交前后校验均保留。

### 其他体积来源

- 错误表：51 个标签，约 4.7 KB。集中维护并避免每次调用重新创建对象；错误码与文案未改。
- Patch 数据：8 个区间。新增版本/hash 索引会抵消部分文本复用的体积收益。
- 常量：ports 和主要路径已有集中定义。本轮仅整理 Controller patch 的版本引用、原始 hash 来源及已补丁 hash。
- 可生成配置：已有 profile delta、托管键列表及 helper 依赖表，保持现状。
- 注释：保留 patch、compatibility、transaction、许可证和测试定位标记，未删除安全约束说明。
- 重复字符串：协议字段、错误码和日志字段存在消费者，未缩写或改名。
- 重复 Shell：仅复用四处完全相同的 Service 候选 patch 准备与收尾文本。

## 二、v9.1 cleanup 方案与实施

方案名称为 v9.1 cleanup；本轮没有升级插件或 Controller 版本。

实施前保守预计体积减少 0–0.2%，风险为低；无法证明输出一致的候选放弃。实施后实际减少 0.0193%。

| 步骤 | 实施内容 | 行为一致证据 |
|---|---|---|
| 1 | HTTP patch 数组整理为版本 → 原始 Controller hash → patch 列表 | 8 个区间及顺序不变；生成 HTTP patch Shell 逐字节一致 |
| 2 | 集中版本引用和已补丁 hash；从 registry 取得原始 hash | 白名单仍仅接受原始及已补丁构建；未知 hash 拒绝及已 patch 跳过测试通过 |
| 3 | 将 labels 提升为 `F50_DIAGNOSTIC_LABELS` | 51 个键和值一致；1,029 组输入的全部返回字段一致 |
| 4 | 在原 Service patch 构造器内复用 `patchSetup` / `patchFinish` 文本 | 缩进也保持一致，生成 Shell 逐字节相同 |
| 5 | 更新离线 patch 工具和测试提取范围 | 补丁生成校验保留；夹具包含其实际使用的常量 |

每一步检查了局部 diff。原始逻辑保留在 Git 基线 `b21155e`，回归直接读取该版本比较。

## 四、风险与未改变范围

源代码语义比较仅允许三个函数及三个数据常量发生 cleanup 变化；其余 AST 语义完全一致。37 个脚本、命令或条件构造器在全部覆盖变体中生成结果一致：49 份 Shell 输出通过 `sh -n` 与 BusyBox `ash -n`，另一个构造器输出 yq 条件表达式。

以下保持原样：

- `F50_COMPAT_VERSION`、Controller 字段及输出协议。
- `F50_DEFAULT_SECRET` 的声明和值，以及原有 secret 保留/补全逻辑。
- TProxy、TUN、DNS、IPv4、IPv6、路由、规则归属及共享路由保护。
- 安装事务、配置事务、恢复资格、锁归属、任务回执及状态机。
- 所有安全校验、patch/compatibility/transaction marker 和执行顺序。
- 组件包 `tproxy-yq.zip` 与本地私有 F50 配置。

剩余验证边界：本轮没有在 F50 上安装、启停服务、执行恢复或测试真实网络流量。本地与 ARM64 仿真通过不能替代这些设备结果。
