猫猫 TProxy 今日提交总结｜10 月 19 日

今天共 7 个提交，重点集中在恢复与任务回执、卸载兼容、安全审计，以及一轮全量文案与冗余清理。

一、恢复与任务回执
- 完成回执现在保存退出码和命令输出；释放租约前先校验回执，避免把未完成任务当成已完成。
- 响应丢失时按原请求编号补查结果，不重复执行命令；补查失败会明确报错，不再停留在“未知”。
- 恢复流程会识别并清理 .output / .receipt 中间文件；rescue_PID 锁只在原进程已退出时接续。
- 恢复资格检查补充 age、cp、mv、rm 等进程名，减少“未知持有者”误判。

二、卸载与手动恢复
- 卸载允许在“上次任务结果未知”时启动：先回收闲置租约，再进入卸载；某个阶段失败会记录并停止后续阶段。
- 安装锁区分活跃与陈旧：PID 不存在且目录干净才按陈旧锁清理；手动恢复/卸载会清掉这类锁。
- 卸载前先恢复 config.yaml / template 事务，再删除组件；开机项中的 Gist 区块整段移除。
- 手动恢复会调用原生 recover 处理 download / rp-filter / legacy-policy journal，并记录返回码。

三、安全与输入校验
- 控制 API 的 curl 配置改走 stdin（-K -），认证头和正文不再进入 curl 参数。
- Gist 请求体改用 printf 管道传入，避免 heredoc 被内容提前终止；新增命令注入用例。
- 配置包导入先列目录并校验路径，拒绝绝对路径、..、反斜杠和控制字符，再按 ZIP/TAR 解压。
- JS 覆写 Worker 禁用 Function / eval 并冻结构造器链；随机串优先使用 crypto.getRandomValues。
- IPv4 DNS 旁路与私网网段增加地址格式校验；YAML 导出拒绝 NaN / Infinity。
- 配置导出改为在 /data 私有目录暂存打包，成品 5 分钟后自动删除；上传临时文件成功或失败都会清理。
- 审计修复未改动既有凭据默认值，升级不会改变面板密钥。

四、文案与菜单
- 全量统一提示句式、标点和术语（组件包、核心、节点来源、运行配置），约 400 条。
- 修正提示指向不存在的菜单：订阅链接→订阅设置、模板与覆写→配置与规则、应用模板与覆写→配置与规则→应用模板。
- 统一名称：直连设备、私网定向代理、订阅 User-Agent、导入/导出配置包、保存并更新订阅、添加 IP/MAC、安装/启动、Mihomo 大小写。
- 传输异常提示改为“无法确认下载结果”，区分“结果未知”和“响应读取失败”。

五、冗余与性能
- 删除重复取消判断、失效的 typeof 守卫、allSettled().catch 死捕获、两处不可达兜底。
- 合并订阅更新中重复的配置来源读取，每次更新少一次设备 root shell 往返。

六、测试与文档
- 扩展 reliability、ipv6_dns、rc3-ui 用例；更新 RECOVERY_AND_TRANSACTION、SECURITY_MODEL。
- 相关测试：cleanup 40/40、compact 2/2、panel 16/16、subscription 33 通过 / 2 跳过。

七、影响与关注
- 影响范围：安装/卸载/恢复、订阅更新、Gist、配置导入导出、JS 覆写、网络设置。
- 失败与“未确认”已分开；任务回执和租约校验更严格，异常时先看“状态与日志”。
