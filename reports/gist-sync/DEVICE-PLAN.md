目标设备为 `192.168.0.1`，运行 TProxy。用户已确认“允许备份后安装升级，暂不切换模式”。下列备份及升级已执行，安装和事务收尾成功；配置、来源、策略哈希与备份一致，核心 API 为 200。证据见 `device-install.json`、`device-postcheck.json` 与 `evidence.jsonl`。

本次执行顺序及恢复约束：

1. 重新只读记录核心 PID、架构、模式、配置/来源/组件哈希及空间。条件变化时停止安装调查。
2. 在 `/data/local/tmp/maomao-rc4-backup-<UTC时间>` 建立 0700 备份目录，将 `/data/clash` 和 `/sdcard/ufi_tools_boot.sh` 完整备份，记录逐文件哈希并复核；保留路由、规则、接口、iptables/ip6tables 状态。备份留在设备 root 专用目录，私钥及配置内容不输出到普通日志。
3. 验证局域网设备管理接口和 ttyd 可独立访问。保留原组件及原 JS，在需要时可回到原组件管理执行恢复；不以重启替代故障恢复。
4. 使用原组件管理的“导入组件包”安装候选，允许安装器短暂停止并恢复核心。不切换 TProxy/TUN/Off 模式。
5. 分别检查组件校验/可执行性、安装状态及事务收尾状态。配置及来源哈希必须与安装前相同；Controller 协议不变，原 Mihomo 正常，后台调度器至多一个。
6. 如失败，优先按安装事务报告中的备份路径恢复；不清理未完成事务，不反复覆盖安装。必要时用已保留的原目录、原开机脚本和原服务恢复原模式，先复核再清理。
7. Gist 生产端到端解密还需用户在可信设置入口提供私钥或独立测试 Gist；没有密钥时只确认组件就绪和正确错误分类，不伪造同步成功。

真实网络模式切换、重启及长时间后台同步为后续单独确认项，不包含在本次“仅安装升级”授权中。Android WebView 尚无授权 ADB/屏幕入口，普通桌面浏览器不能代替。
