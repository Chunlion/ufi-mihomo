## fake-ip 是否被插件覆盖（结论：不覆盖）

三处代码证据，`enhanced-mode` / `fake-ip-*` / `store-fake-ip` 全程不受控：

1. `CONTROLLED_DNS_KEYS = ['enable','listen','ipv6']`（`猫猫TProxy.js:55`），`F50_ORIGINAL_DNS_KEYS` 同值。
2. `runtime()`（2939）`preserveConfig=false` 时先 clone `profile`（含 redir-host），但循环里 `key === 'dns'` 走 `mergeDnsValue(out.dns, source.dns)`（2903）：深合并且**用户值优先**，只用 profile 覆盖那 3 个受控键。
3. `Scripts/Clash.Service` 的 `f50_restore_original_config` 用 yq：`.dns = ($original.dns * ($runtime.dns | pick(["enable","listen","ipv6"])))`（354 行），反向写回时 `omit(["enable","listen","ipv6"])`（361 行）。`repair_panel_config` 不碰 dns。

`preserveConfig` 只在 `configSource === 'subscription_original'` 时为 true（3063），其余走 mergeDnsValue，所以两条路都保 fake-ip。

## fake-ip 实测（WSL + 同版本 amd64 v1.19.33）

`mihomo -t` 通过。起实例后 `dig @127.0.0.1 -p 11053`：google.com / www.qq.com / example.org / api.telegram.org 全部返回 `198.18.0.4~7`，fake-ip 确实生效。

但暴露一个真坑：`rule-providers` 全部 `proxy: 一键代理`，无可用节点时 `全局最优` 是 `url-test + empty-fallback: REJECT` → 规则集下载被 REJECT（日志 `[TCP] mihomo --> raw.githubusercontent.com:443 using 一键代理[REJECT]`）→ `fake-ip-filter` 里的 `rule-set:cn_domain` 失效 → **国内域名也拿 fake IP**，全落到兜底组走代理。redir-host 下同类故障表现为「拿真实 IP 但分流不准」，fake-ip 下会直接绕路。有节点时自愈。

## 判定组件包模板是否被插件改写

`applyRequiredF50Fields`（`preserveConfig: true`，模板无 generated 标记时）只补 `external-controller`/面板字段/`secret`/`proxies`；`normalizeManagedTemplateObject` 会**重建** `proxy-providers` 并给含 `use`/`filter`/`include-all` 的组强制写 `use = providerNames`。所以模板里的 `proxy-providers` 名字和 URL 在首次「准备模板」时会被插件接管，能长期保留的是 groups/rules/rule-providers。
