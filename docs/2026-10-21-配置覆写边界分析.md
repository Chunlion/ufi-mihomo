# YAML 配置覆写边界分析

分析对象：`猫猫TProxy.js` 的配置整形链路
分析方式：静态调用链 + 键级比对（未做实机写入验证，验证方法见第 6 节）

## 1. 结论

配置整形只有一条主链路，但有两个截然不同的分支，分界线是 `config_source`：

```js
// 猫猫TProxy.js:2932
const preserveConfig = (configSource === null ? await readConfigSource() : configSource) === 'subscription_original';
// :2836
const out = clone(preserveConfig ? source : profile);
```

| 分支 | 适用场景 | 基线 | 用户字段去留 |
|---|---|---|---|
| `preserveConfig = true` | 配置来源为 `subscription_original` | 用户配置 | 除受控键外全部保留 |
| `preserveConfig = false` | **默认路径**：模板规则、订阅生成、网络设置保存、配置自检修复、Gist 应用 | `F50_FIXED_PROFILES` | 只保留 9 个顶层键 |

也就是说：**只要不是「原始订阅配置」模式，用户配置里除 9 个白名单键之外的一切都会被 profile 覆盖或丢弃**。白名单在 :2840：

```
proxies, proxy-providers, proxy-groups, rules, rule-providers,
sub-rules, hosts, secret, x-f50-provider-sources
```

`x-` 前缀键会被保留（:2838），但前提是 profile 里没有同名键。`dns.proxy-server-nameserver-policy` 是唯一被单独放行的 dns 子键（:2855）。

上传的自定义配置（`uploaded_config`）**不享受** `preserveConfig`。它在订阅更新路径上被特殊保护（:10738、:10799），但一旦走「配置自检与修复」（:8353 → :8377）或 Gist 应用，仍按 profile 重建。这是当前最容易被用户感知的过度覆写场景——用户上传完整配置的意图就是完全控制。

## 2. 过度覆写点位

「必要」列指：该字段是否真的被硬件或脚本逻辑依赖。标记「不必要」的就是可以放行的部分。

| # | 点位 | 代码位置 | 覆写行为 | 被覆盖的用户字段 | 必要性 |
|---|---|---|---|---|---|
| 1 | `dns` 整组 | :35 `PROFILE_BASE.dns` | 非 preserve 分支整体替换 | `nameserver`、`fallback`、`fallback-filter`、`nameserver-policy`、`hosts`、`fake-ip-filter`、`respect-rules`、`prefer-h3`、`use-hosts` | 仅 `enable`/`listen`/`ipv6` 必要 |
| 2 | `sniffer` 整组 | :35 | 整体替换 | `skip-domain`、`skip-dst-address`、`sniff.*.ports`、`override-destination`、`enable` | 不必要 |
| 3 | `profile.store-fake-ip` | :35 | 强制 `false` | 用户设为 `true` 会被改回 | 不必要（与 `enhanced-mode` 联动，放行需提示） |
| 4 | `profile.store-selected` | :35 | 强制 `true` | 用户设为 `false` 会被改回 | 不必要 |
| 5 | `tun.mtu` | :39-:40 | 强制 `1500` | 用户自定义 MTU（如 9000、1400） | 不必要（≥1280 即可） |
| 6 | `tun.stack` | :2858 | 由 `f50TunStack(options)` 覆盖 | 用户在配置里写死的 `stack` | 部分必要（旧内核需回退），已有版本门槛 |
| 7 | `tun.device` / `auto-route` / `auto-redirect` / `strict-route` / `dns-hijack` | :39-:40 | 强制固定 | 用户自定义 TUN 路由与设备名 | 必要（与 clashctl 路由管理冲突） |
| 8 | `log-level` | :35 | 强制 `info` | `debug` / `warning` / `silent` | 不必要 |
| 9 | `find-process-mode` / `geodata-mode` / `geodata-loader` / `geo-auto-update` | :35 | 强制固定 | 用户调优值 | 不必要 |
| 10 | `port` / `socks-port` / `mixed-port` | :35 | 强制 7890/7891/7892 | 用户自定义本地代理端口 | 不必要（仅 `tproxy-port`、`dns.listen` 被 iptables 依赖） |
| 11 | 节点级 `interface-name` / `routing-mark` | :2865-:2866 | **所有模式**都删除（含 preserve） | proxies、proxy-groups 里每个节点的这两个字段 | 不必要（Android 上大概率无效，但属于静默删除） |
| 12 | `provider.override` 内的 `interface-name` / `routing-mark` | :2870 | 同上，所有模式删除 | provider 级绑定字段 | 同上 |
| 13 | `rule-providers.*.proxy` | :2871 | 非 preserve 时 `type: http` 的 provider 强制 `proxy: DIRECT` | 用户指定走代理下载规则集 | 部分必要（避免 curl 走代理失败），应给开关 |
| 14 | `dns.nameserver-policy` 注入 | :2874-:2878 | 覆盖写入 `rule-set:cn_domain` 等三条 | 用户同名策略 | 部分必要，应 merge 而非覆盖 |
| 15 | `external-ui` / `external-ui-url` | :5755-:5766 | **无条件**覆盖（含 preserve） | 用户换面板、自建 UI 地址 | 必要（`buildF50PanelConfigCheck` :611 校验固定值） |
| 16 | `unified-delay` | :5765 | 非 preserve 强制 `true` | 用户设为 `false` | 不必要 |
| 17 | `external-ui-name` | :5766 | **无条件**删除（含 preserve） | 用户显式设置的别名 | 必要（面板校验要求 `has("external-ui-name") \| not`） |
| 18 | `proxy-groups[].use` | :5815-:5828 | 只要组里有 `use`/`include-all`/`filter`，就把 `use` 覆盖为**全部** provider 名 | 用户只想让某组用部分订阅 | 不必要 |
| 19 | `rules` 整体重建 | :5872-:5881 | `rules` 为空或 `generated` 时用内置 `buildManagedFallbackRules` 替换 | 用户规则（仅 `generated` 场景） | `generated` 时合理，非 generated 时不应触发 |
| 20 | `GEOIP,private/netflix/telegram/google` 规则 | :5850、:5859 | 静默过滤删除 | 用户保留的分类 geoip 规则 | 部分必要（新内核已移除分类 geoip） |

### 顺带发现的三个死参数/参数名错误

| 位置 | 问题 | 后果 |
|---|---|---|
| :5952 | `applyRequiredF50Fields(config, { managedDashboard: generated })`，但 :5770 的签名是 `{ preservedSecret, preserveConfig }` | `generated` 从未传入，`preserveConfig` 恒为 `false` → 模板模式下 `unified-delay` 永远被强制写 `true`、`external-ui-name` 永远被删，即使 `generated=false` |
| :6502 | `normalizeManagedTemplateObject(..., { tproxyPort })`，但 :5945 的签名没有 `tproxyPort` | 传入即丢弃 |
| :5682 | `detectF50TproxyPort = async () => F50_PORTS.tproxy` | 恒返回常量 7895。`options.tproxy_port`（:2981 有该键、UI 有该项）**从不参与配置生成**，改端口一定被覆写成 7895 |

## 3. 安全边界

### 必须固定（动了会直接坏）

| 键 | 原因 | 证据 |
|---|---|---|
| `external-controller` | Controller/Service/clashctl 按固定 7788 建连 | `F50_PORTS.controller`、`buildControllerInfo` |
| `external-ui` / `external-ui-url` | 启动前校验面板身份 | `buildF50PanelConfigCheck` :611 |
| `external-ui-name`（必须不存在） | 同上，校验表达式要求该键缺失 | :611 |
| `tproxy-port` / `dns.listen` | iptables/ip rule 与 DNS nat 按固定端口下发 | `F50_PORTS.tproxy=7895`、`dns=1053` |
| `bind-address`、`ipv6` | 策略脚本按 tproxy4/6 分支建规则 | `PROFILE_DELTA` |
| `tun.device`、`auto-route`、`auto-redirect`、`strict-route`、`dns-hijack` | 与 clashctl 的路由管理和插件自身 DNS nat 冲突 | :39-:40、README 网络模型 |
| `mode: rule` | 私网定向代理依赖规则模式，`transform` 会直接报错 | :2800 |
| `allow-lan: true` | 下游设备接管的前提 | `PROFILE_BASE` |
| `secret` 非空 | API 鉴权 | :5779 |
| `x-f50-profile` | 版本标记，供恢复与诊断使用 | :2879 |

### 可放行（不影响上述契约）

| 键 | 放行条件 |
|---|---|
| `dns.nameserver` / `fallback` / `fallback-filter` / `nameserver-policy` / `hosts` / `fake-ip-filter` / `use-hosts` / `respect-rules` / `prefer-h3` | 保留 `enable`/`listen`/`ipv6` 三个受控键即可 |
| `dns.enhanced-mode` | 可放行，但与 `profile.store-fake-ip` 联动，切换时提示一次 |
| `sniffer` 整组 | 无需条件；`skip-dst-address` 只是性能优化 |
| `log-level`、`find-process-mode`、`tcp-concurrent`、`keep-alive-interval`、`geodata-*`、`unified-delay` | 无需条件 |
| `profile.store-selected` | 无需条件 |
| `profile.store-fake-ip` | 与 `enhanced-mode` 一致时允许 |
| `tun.mtu` | `≥1280` |
| `tun.stack` | 放行但保留 `f50TunStack` 的版本门槛与回退 |
| `port` / `socks-port` / `mixed-port` | 与 `tproxy-port` 不冲突即可（三者互不重复、不等于 7895/1053/7788） |
| 节点 `interface-name` / `routing-mark` | 需实机确认 Android 上 Mihomo 是否支持；不支持时应在写入前提示而非静默删 |
| `rule-providers.*.proxy` | 给「规则集走代理下载」开关 |
| `proxy-groups[].use` | 只校验引用的 provider 名存在 |

## 4. 优化建议

### P0 修死参数（纯 bug，无行为风险）

1. :5952 改为 `applyRequiredF50Fields(config, { preserveConfig: !generated })`——至少让 `generated` 语义生效。
2. :6502 的 `tproxyPort` 要么接入 `normalizeManagedTemplateObject`，要么删掉。
3. :5682 让 `detectF50TproxyPort` 读 `options.tproxy_port` 并与 iptables 下发端口统一，否则从 UI 移除该选项。

### P1 把「profile 为底」改成「用户为底 + 受控键覆盖」

`runtime()` 两个分支合并成同一套逻辑：

```js
const out = clone(source);                     // 永远以用户配置为底
for (const key of CONTROLLED_TOP_KEYS) out[key] = clone(profile[key]);
mergeControlledDns(out.dns, profile.dns);      // 只覆盖 enable/listen/ipv6
mergeControlledTun(out.tun, profile.tun, mode); // 只覆盖路由/设备/dns-hijack
```

把受控集合收敛到第 3 节「必须固定」的 10 项。这是收益最大的一步：一次性解决点位 1~10。

### P2 子键合并而非整组替换

`dns`、`sniffer`、`tun` 改成 `{ ...userValue, ...controlledKeys }`，`nameserver-policy` 用 `{ ...userPolicy, ...kanoPolicy }`（点位 14）。`proxy-groups[].use` 只在引用了不存在的 provider 时才裁剪（点位 18）。

### P3 保留清单 + 冲突提示

整形时收集被覆盖的键，写入 `x-f50-overridden` 并在「配置自检」里展示「本次保存覆盖了你设置的 X/Y/Z」。用户至少知道发生了什么，而不是保存后发现配置变了。

### P4 兼容性删除改为事后处理

`GEOIP,private/netflix/telegram/google`（点位 20）不要静默删除，改为写入后跑 `Core -t`，仅在报错时按报错规则回删。同理 `rule-providers.*.proxy`（点位 13）给开关而不是硬改。

## 5. 风险与不做的事

- **不要**放行 `tproxy-port`、`dns.listen`、`external-controller`：iptables 规则、Service、面板校验三处硬编码，改了就是全链路不一致。
- **不要**放行 `tun.auto-route` / `strict-route`：与 clashctl 的路由管理是二选一关系，同时开会产生互相覆盖的路由。
- **不要**为了让用户"完全自由"就删掉 `x-f50-profile` 与 `GENERATED_TEMPLATE_MARKER`：恢复和事务逻辑依赖它们判断配置来源。

## 6. 验证方法

1. **键级差分测试**：构造一份包含自定义 `sniffer`、`dns.nameserver`、`dns.hosts`、`tun.mtu=1400`、`log-level=debug`、节点 `interface-name` 的配置，过 `KPR.runtime` 后断言这些键原样保留，同时断言受控键等于 profile。建议加进 `tests/tproxy/yaml_bridge.test.js`。
2. **受控集合回归**：把「必须固定」的 10 个键逐个改值，断言整形后都被纠正——防止将来放行过头。
3. **模板生成不误伤**：`generated=false` 且 `rules` 非空时，断言 `rules` 与 `proxy-groups` 不被替换（对应点位 19 与 :5952 的修复）。
4. **实机确认**：`interface-name` / `routing-mark` 在 Android 上是否被 Mihomo 接受，决定是放行还是保留删除但加提示。
