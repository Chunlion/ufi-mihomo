## 模板里的 example.com 占位符会不会出问题（11:35 查证）

结论：**走「应用模板」不会**，因为 `normalizeManagedTemplateObject`（`猫猫TProxy.js:6071`）先 `delete config['proxy-providers']`，再用 `buildManagedProxyProviders(sources, {emptyUrls:true, ensureOne:true})` 整块重建。`emptyUrls` 时构建出的 provider 连 `url` 字段都不写：

```js
{ type: 'file', path: './proxies/<source.name>.yaml',
  'health-check': { enable: true, url: 'https://www.gstatic.com/generate_204', interval: 900 } }
```

三个真实后果：

1. **不能把脱敏版当 `uploaded_config` / Gist 的配置源** —— 那条路径不重建 provider，`example.com` 会被真的去请求 → 0 节点。Gist 里必须放含真实订阅的 `F50.yaml`。
2. **模板里的 `filter:` 会丢**（过滤广告/信息节点的正则）和 `override: {additional-prefix: ''}`。重建只给 type/path/health-check，所以「应用模板」比「走 Gist」多出广告节点。
3. **provider 名会变**：模板写 `机场1`，重建后按保存的订阅名（设备上是 `Provider1`）。
4. `type: file` 指向 `Proxy/proxies/<name>.yaml`，包内那个文件只有 `{"proxies":[{"name":"NotConfigured","type":"direct"}]}` —— 用模板但没更新订阅时，只有一个 NotConfigured 直连节点，看着能连实际没代理。
