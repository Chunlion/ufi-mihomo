## F50 实机测试步骤（未执行）

先在管理页保存原插件、导出配置包，备份 /data/clash/Proxy/config.yaml、Tools/template.base.yaml、Tools/template.yaml、Tools/config_source.conf、Proxy/subscription_urls.txt 和 Policy/options.conf。保存原状态和端口记录，导入交付 JS 后刷新页面。

1. 首次安装在空白测试环境点击“安装 / 启动”；覆盖升级分别在运行和明确停止的状态执行。检查 F50_INSTALL_COMPONENTS_OK、F50_INSTALL_TRANSACTION_STATE、KANO_INSTALL_OK 与界面结果一致。停止态升级不得启动核心，旧配置和密钥应保留。
2. 在“网络设置”依次切换 TProxy / TUN / off，每种分别关闭和开启 IPv6，保存并确认选定状态。通过设备终端读取 ip -4 rule、ip -6 rule、ip -4 route show table all、ip -6 route show table all、iptables-save、ip6tables-save。分别验证 IPv4/IPv6 代理请求、DNS、QUIC、私网 CIDR、设备绕过与 IPv6 返回路由。检查 TUN auto/mixed/gvisor/system/mips；不支持的版本应清晰拒绝。
3. 单条、多条及全部禁用订阅分别保存；检查 Provider1/Provider2、UA、HTTP Provider 与 local 的实际加载结果。使用受控返回 HTTP 390 的测试源触发回退，再用失败源验证配置、设置、节点缓存及核心状态回滚。不要把节点下载成功视为代理连通成功。
4. 在保留 subscription_original 或 original 标记的备份环境打开插件和点“更新订阅”，逐文件比较上述配置，确认没有自动覆盖。点击“保存并更新”并确认迁移，检查备份目录和模板来源；故意让 JS 覆写报错，确认旧模板、基础模板、运行配置与来源全部保留或恢复。上传和编辑自定义 config.yaml 后再次保存订阅，确认未勾选替换时配置保持不变。
5. 打开两个管理页面，同时发起更改；第二页应报告忙。取消或断开一个请求后检查任务记录和租约，确认未收到完成回执时保留锁。分别验证真实活跃任务不能恢复、旧 PID-only 记录不能自动清除，以及带有效终态回执的已结束任务可以在恢复锁内处理。检查没有未完成安装或配置事务。
6. 安装、Service 阶段失败和锁清理故障只在隔离的组件副本和测试目录注入，不破坏正式运行文件。按相应离线测试的注入方式使某一候选阶段、rmdir 或恢复步骤失败；检查正式 Service 哈希不变，失败点清晰，未知锁文件保留，成功组件不会因收尾失败回滚。
7. 正常停止与首次 TUN 停止后检查 KanoTun、detached 规则和受管路由；恢复网络连续执行两次，检查第二次仍可完成、未知路由和外部进程保留。仅在已有事务已处理后测试核心/API 或 Service 不可用时的独立恢复。最后检查卸载、自启和设备重启后的实际进程、DNS、面板及代理连通性。
